# 网站 URI 优秀命名规范（本项目采用）

## 一、通用原则

1. **全小写**：路径仅使用小写字母，避免大小写歧义与规范化问题。
2. **连字符分词（kebab-case）**：多词用 `-` 连接，如 `/forgot-password`，不用下划线或驼峰。
3. **名词为主**：路径表示「资源」或「页面」，用名词或名词短语；动作由 HTTP 方法或子路径表达（如 `/videos/new` 表示「新建」）。
4. **复数表示集合**：资源列表用复数，如 `/products`、`/promotions`、`/videos`。
5. **层级按领域分组**：同一业务域放同一前缀下，便于可读与缓存策略，如 `/auth/*`、`/creator/*`、`/legal/*`。

## 二、层级与可读性

6. **认证统一在 /auth**：登录、注册、忘记密码、验证邮箱、选择角色等均放在 `/auth/` 下，如 `/auth/login`、`/auth/register`、`/auth/role`。
7. **创作者动线在 /creator**：仪表盘、身份认证、可推广产品列表、提交视频等放在 `/creator/` 下；子路径用名词，如 `/creator/products`（待选产品列表）、`/creator/videos/new`（新建视频提交）。
8. **资源详情用 /资源名/:id**：如 `/products/:id`、`/promotions/:id`、`/videos/:id`，避免 `/product-details/:id` 等冗余。
9. **深度适中**：一般 2～3 层（如 `/creator/videos/new`），避免过深影响可读性与路由配置。

## 三、性能与一致性

10. **同一资源一套路径**：列表、详情、新建等保持同一前缀，利于 CDN/缓存规则和开发者心智一致。
11. **旧路径 301 重定向**：调整 URI 后对旧路径做永久重定向，保证外链与书签可用，且利于 SEO 权重收敛到新地址。

---

以上规范用于指导本项目的路由命名与目录结构，兼顾可读性、可维护性与缓存友好。
